### [W3, round 1]
Research Focus: Minimum size of the sumset A+A given fixed range R and size n.

Theoretical Background:
1. Cauchy-Davenport Theorem (and related results for integers): For a set A of integers, the size of the sumset |A+A| is minimized when A is an arithmetic progression (AP).
2. If A is an AP of size n, say A = {a, a+d, ..., a+(n-1)d}, then the sumset A+A is also an AP of size 2n-1.
3. In our specific problem:
    - Size of the set: $n = 87$ ($t_0$ to $t_{86}$).
    - Fixed range: $R = t_{86} - t_0 = 171$.
4. The minimum possible size of $T+T$ for $|T|=87$ is $2(87) - 1 = 173$. This minimum is achieved when $T$ is an AP.
5. The smallest range required for an AP of size 87 with integer steps ($d=1$) is $R_{min} = (87-1) \times 1 = 86$.
6. Since the allowed range $R=171$ is greater than or equal to the minimum required range $R_{min}=86$, we can construct the set $T = \{0, 1, 2, \ldots, 86\}$. This set satisfies the constraints ($|T|=87$, $t_0=0$, $t_{86}=86 \le 171$) and achieves the minimum possible sumset size of 173.

Conclusion: The minimum size of the sumset is 173.

### [W4, round 1]
**Construction of $\{t_i\}$:**
To most closely resemble an arithmetic progression (AP), the differences $d_i = t_{i+1} - t_i$ must be as constant as possible.
We have $N=87$ elements and a span of $D=171$. The average difference is $\bar{d} = 171/86 \approx 1.999$. Since $t_i$ must be integers, the differences must be primarily 2.
We need 86 steps. If all steps were 2, the total span would be $86 \times 2 = 172$. Since we need a span of 171, exactly one difference must be 1, and the remaining 85 differences must be 2.

We choose the sequence where the deviation (the difference of 1) occurs at the very end to maintain the longest possible initial AP structure:
$t_0 = 0$
$t_1, t_2, \ldots, t_{85}$ form an AP with difference 2: $t_i = 2i$.
$t_{85} = 2 \times 85 = 170$.
$t_{86} = 171$. (Difference $t_{86}-t_{85} = 1$).

The constructed sequence is: $\{0, 2, 4, 6, \ldots, 170, 171\}$.

**Determination of Sumset Size:**
The size of the sumset $\{ t_i+t_j \}$ is minimized when the original set $\{t_i\}$ is as dense as possible (i.e., when it closely approximates a standard arithmetic progression).
For a perfect AP of $N$ elements, the sumset is also an AP, and its size is $2N-1$. Our construction ensures that the elements of $T$ are packed as closely as possible given the integer constraints and the fixed endpoints (0 and 171).
The density achieved by setting all differences to 2 (except one) ensures that the resulting sumset $S$ overlaps maximally, leading to the smallest achievable cardinality $|S|$. The overall size is determined by how many distinct sums are generated by the pairing, which is tightly bounded by the linear arrangement of $T$.

### [W2, round 1]
Continuous Limit Case Analysis:
Let t_i = i * d, where d = 171/86. The sumset is S = {(i+j)d | 0 <= i <= j <= 86}.
The sums correspond to integers k = i+j, ranging from 0 to 172.
By testing all pairs (i, j), it was confirmed that every integer k in [0, 172] is achievable as i+j.
Therefore, the minimum size of the sumset in the continuous limit case is 173.

Generalization to Integer Constraint:
If t_i must be integers, they cannot form a perfect arithmetic progression (since 86 does not divide 171). To minimize the sumset size, t_i must be as close to an AP as possible.
We analyzed the best possible integer approximation (t_i increases mostly by 2, with one jump of 1). This specific integer sequence yielded a minimum sumset size of 258, significantly larger than 173.
The generalization is that while the continuous minimum size is 173, the integer constraint forces the sumset size to be strictly larger due to unavoidable gaps caused by the sequence not being a perfect AP. The theoretical minimum size remains 173, acting as a lower bound.
